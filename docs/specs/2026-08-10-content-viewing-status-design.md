# 작품별 시청 상태 설계

- 작성일: 2026-08-10
- 상태: 승인

## 목표

로그인 사용자가 작품마다 다음 상태 중 하나를 저장하고 작품 페이지에서 바꿀 수
있게 한다.

- 보는 중 (`watching`)
- 다 봤음 (`completed`)
- 보다 말았음 (`dropped`)
- 관심 있음 (`interested`)

## 데이터 모델

상태는 개별 감상 기록이 아니라 사용자와 작품의 관계다. 한 작품에 기록이 여러
개 있어도 상태는 하나만 유지하고, 기록이 없어도 상태를 저장할 수 있도록
`user_content_statuses` 테이블로 분리한다.

```text
user_id + content_id (PK)
status                  CHECK(watching|completed|dropped|interested)
```

기존 기록에서 상태를 추론하지 않는다. 날짜나 기록 개수만으로 보는 중과 다 봤음을
정확히 구분할 수 없기 때문이다. 기존 사용자 상태의 초깃값은 미설정(`null`)이다.

## API

- `GET /api/content/:id/mine`: 기존 `entries`와 함께 `viewingStatus`를 반환한다.
- `PUT /api/content/:id/status`: `{ viewingStatus }`를 검증하고 사용자·작품 행을
  upsert한다. `null`이면 상태 행을 삭제한다.
- 두 엔드포인트 모두 기존 인증 게이트 뒤의 `entriesRoute`에 둔다.
- 상태 변경 대상 작품이 없으면 `PUT`은 `404 not_found`, 네 값 이외 입력은
  `400 invalid_input`을 반환한다. 기존 `GET /mine`의 빈 응답 계약은 유지한다.

## UI

로그인한 사용자의 작품 페이지 `내 기록` 카드 상단에 네 상태를 고르는 네이티브
`select`를 표시한다. 미설정을 고르면 상태를 해제한다. 저장 중에는 중복 요청을 막고,
실패하면 기존 선택을 유지한 채 오류 문구를 표시한다.

## 범위 밖

- 대시보드의 상태별 목록·필터·집계
- 검색 결과에서 기록 없이 관심 작품을 새로 저장하는 흐름
- 상태 공개 및 공개 프로필 노출
- 기록 생성 시 상태 자동 변경
- 기존 기록을 바탕으로 한 상태 자동 추론

## 검증

- API: 생성·변경, 사용자 간 격리, 잘못된 상태와 없는 작품 거부
- 웹: 네 상태와 현재 선택의 접근성 속성 렌더링
- 다국어 키 일치, 전체 테스트, 타입 검사, 웹 프로덕션 빌드

# 게스트 모드 설계

- 작성일: 2026-08-06
- 대상: `apps/web`, 공개 검색 API
- 상태: 승인

## 목표

로그인하지 않은 사용자가 임의의 게스트 이름으로 기록 기능을 사용한다. 게스트
프로필과 시청 기록은 현재 브라우저의 `localStorage`에만 저장하며 D1에는 쓰지
않는다.

## 동작

- 로그인 화면의 `게스트로 시작하기`를 누르면 `guest_<8자리>` 이름을 생성한다.
- 기존 게스트 데이터가 있으면 이름과 기록을 그대로 재사용한다.
- 게스트 이름, 활성 상태, 기록을 하나의 버전된 `localStorage` 값에 저장한다.
- 기록 생성·조회·수정·삭제와 잔디 집계는 브라우저에서 수행한다.
- `게스트 종료`는 기록을 삭제하지 않고 활성 상태만 해제한다.
- 로그인 세션이 있으면 게스트 활성 상태보다 로그인 세션을 우선한다.
- 게스트 화면에는 데이터가 현재 브라우저에만 저장된다는 안내를 항상 표시한다.

## 서버 경계

- 게스트 기록, 이름, 감상, 반응은 서버 API로 전송하지 않는다.
- 작품 검색과 YouTube 메타데이터 조회는 기존 프록시를 읽기 전용 공개 경로로
  사용한다. 이 경로는 D1을 읽거나 쓰지 않는다.
- 게스트용 DB 테이블, 세션, API CRUD 엔드포인트는 추가하지 않는다.
- 로컬 작품은 서버의 `/c/:contentId`에 존재하지 않으므로 게스트 화면에서 작품
  상세 링크를 제공하지 않는다.

## 범위 밖

- 게스트 기록의 계정 전환·서버 동기화
- 여러 브라우저 또는 기기 간 동기화
- 게스트 공개 프로필, 팔로우, 연합우주
- 가져오기·내보내기

## 검증

- 게스트를 처음 시작하면 이름과 빈 기록이 저장된다.
- 종료 후 다시 시작하면 같은 이름과 기록을 복원한다.
- 기록 CRUD가 `localStorage`만 변경한다.
- 날짜별 잔디 개수와 단계가 기존 규칙과 같다.
- 로그인 없이 검색 API를 호출할 수 있지만 게스트 기록 API는 여전히 401이다.

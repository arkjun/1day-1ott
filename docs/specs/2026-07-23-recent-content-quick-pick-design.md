# 최근 기록 작품 빠른 선택 UI/UX 설계

- 작성일: 2026-07-23
- 대상: `apps/web` 기록 추가 모달
- 상태: 제안

## 배경과 목표

같은 작품을 연속해서 보거나 여러 회차에 걸쳐 기록할 때마다 작품명을 다시
검색해야 한다. 기록 추가 모달에서 선택한 유형별로 최근에 기록한 서로 다른 작품
최대 5개를 바로 선택할 수 있게 해 반복 검색을 줄인다.

성공 기준:

- 최근 작품은 모달을 연 뒤 한 번의 클릭으로 선택할 수 있다.
- 작품을 선택한 뒤 날짜·반응·감상 입력 및 저장 흐름은 기존과 같다.
- 최근 작품과 일반 검색 결과가 같은 선택 완료 UI를 사용한다.
- 추가 네트워크 요청 없이 기존 기록 목록을 재사용한다.

범위 밖:

- 즐겨찾기·고정 작품
- 최근 목록 편집 또는 개별 삭제
- 추천 알고리즘
- 작품별 기본 반응·감상 복사

## 정보 구조

기록 추가 모달의 순서는 다음과 같다.

1. 제목과 닫기
2. 작품 유형 탭
3. 최근 기록한 작품
4. 작품 검색 또는 직접 입력
5. 날짜, 반응, 감상
6. 기록하기

최근 작품은 유형 탭 아래, 검색창 바로 위에 둔다. 사용자는 먼저 빠른 선택을
확인하고, 원하는 작품이 없을 때 바로 아래 검색을 이용한다.

## 기본 화면

최근 작품이 하나 이상일 때만 영역을 노출한다.

```text
최근 기록

[포스터] [포스터] [포스터] [포스터] [포스터]
  무빙      폭싹       ...

[ 작품명을 검색하세요                         ]
```

- 레이블: `최근 기록`
- 선택한 유형별 최대 5개, 왼쪽부터 최근순
- 항목: 2:3 비율 포스터 + 한 줄 제목
- 포스터가 없으면 유형 아이콘과 중립 배경을 사용한다.
- 긴 제목은 한 줄 말줄임 처리하고 전체 제목은 `title` 속성으로 제공한다.
- 데스크톱에서는 5개가 모달 폭 안에 들어가게 배치한다.
- 좁은 화면에서는 카드 폭을 유지하고 가로 스크롤한다. 마지막 카드 일부가
  보이도록 해 스크롤 가능성을 암시하며 스크롤바는 숨길 수 있다.
- 카드 전체가 `button`이며 최소 터치 영역은 44px 이상으로 한다.

### 유형 탭과의 관계

최근 목록은 현재 선택된 유형의 작품만 보여준다. 유형 탭을 변경하면 해당 유형의
최근 작품 최대 5개로 목록이 바뀐다. 각 카드에는 포스터가 없는 경우 유형
아이콘을, 접근 가능한 이름에는 작품명을 포함한다.

최근 카드를 선택하면 해당 작품 자체의 `type`을 사용한다.

## 상호작용

### 최근 작품 선택

카드를 누르면 기존 검색 결과를 고른 것과 동일하게 `picked` 상태로 전환한다.
선택 완료 프리뷰에 포스터, 제목, 유형을 표시하고 검색창과 최근 목록은 함께
숨긴다. 이후 날짜·반응·감상을 입력해 저장한다.

최근 기록에서 얻을 수 없는 검색 상세 정보(평점, 개요, 장르)는 프리뷰에
빈칸으로 두며, 이를 채우기 위한 재검색은 하지 않는다.

### 작품 변경

프리뷰의 `변경`을 누르면 선택을 해제하고 최근 목록과 검색창을 다시 보여준다.
사용자가 이미 입력한 날짜·반응·감상은 유지한다. 기존 `reset()`이 YouTube URL과
검색어까지 비우는 동작도 그대로 유지한다.

### 검색 시작

사용자가 검색창에 한 글자라도 입력하면 최근 목록은 숨긴다. 검색어를 모두
지우면 다시 나타난다. 검색 결과와 최근 목록이 동시에 보여 시선이 분산되는
것을 막기 위함이다.

### 키보드와 포커스

- 모달을 열면 기존처럼 검색창에 포커스한다.
- 최근 카드에는 Tab으로 순서대로 접근할 수 있다.
- Enter 또는 Space로 선택한다.
- 선택 후 포커스는 선택 완료 프리뷰의 `변경` 버튼으로 이동시키는 것을
  권장한다. 구현 난도가 커지면 1차 버전에서는 자연스러운 DOM 포커스 순서를
  유지해도 된다.

## 데이터 정의

`App.tsx`가 이미 `api.listEntries()` 결과를 최신순으로 가지고 있으므로 새 API를
추가하지 않는다. 목록에서 `contentId`가 처음 등장한 항목만 남겨 유형별 최대
5개를 구한다.

```ts
interface RecentContent {
  contentId: string;
  type: ContentType;
  title: string;
  posterUrl: string | null;
}
```

여기서 “최근”은 현재 기록 목록의 정렬 기준인 `watchedOn DESC`, 같은 날짜에서는
`createdAt DESC`를 따른다. 동일 작품을 여러 번 기록했더라도 카드 하나만 보인다.
다국어 제목과 포스터는 목록 API가 이미 해석한 값을 그대로 쓴다.

`App.tsx`에서 `useMemo`로 중복 제거 후 `RecordModal`에 전달한다.

```tsx
<RecordModal
  recentContents={recentContents}
  onClose={() => setOpen(false)}
  onSaved={refresh}
/>
```

최근 카드를 `SearchResult`로 강제로 변환하지 않고, `RecordModal` 내부 선택 상태를
저장에 필요한 공통 타입으로 넓힌다. 검색 결과 선택에는 외부 ID를, 최근 작품
선택에는 `contentId`를 보관한다.

### 생성 API 계약 보완

최근 목록 응답에는 `tmdbId`와 `ytId`가 없고, 현재 생성 API는 외부 ID가 없는
입력을 항상 새 콘텐츠로 만든다. 따라서 제목·포스터만 재전송하면 같은 작품의
`content` 행이 중복 생성된다. 빠른 선택은 기존 작품에 새 기록을 연결해야 하므로
`EntryInput`에 선택적인 `contentId`를 추가한다.

```ts
contentId: z.string().min(1).optional()
```

- 최근 작품 선택: `contentId`, `type`, `title`, `posterUrl`, 기록 메타를 전송한다.
- 검색 결과 선택: 기존처럼 `tmdbId` 또는 `ytId`를 전송한다.
- API는 `contentId`가 있으면 해당 콘텐츠의 존재를 확인하고 그 ID를 사용한다.
- 존재하지 않는 ID는 `400 invalid_content`로 처리한다.
- `contentId`와 `tmdbId`/`ytId`가 함께 오면 `contentId`를 우선하는 묵시적 규칙을
  두지 않고 스키마 검증에서 거부한다. 클라이언트 버그를 조기에 드러내기 위함이다.
- 콘텐츠는 사용자 소유 리소스가 아니라 공유 작품 엔터티이므로, 존재하는 ID에
  기록을 연결할 때 별도의 소유권 검사는 필요하지 않다. 기록의 `userId`는 인증
  세션에서만 가져온다.

## 상태와 예외 처리

- 기록 0개: 최근 영역 자체를 표시하지 않는다.
- 서로 다른 작품이 5개 미만: 있는 만큼만 표시한다.
- 동일 작품 반복 기록: 가장 최근 항목 하나만 표시한다.
- 포스터 없음: 레이아웃이 흔들리지 않도록 동일 크기 플레이스홀더를 표시한다.
- 목록 로딩 실패: 기존 대시보드 오류 처리에 맡기고 최근 영역을 표시하지 않는다.
- 저장 성공: 기존 `refresh()`로 기록 목록이 갱신되어 다음 모달 오픈부터 순서가
  반영된다.
- 검색어 입력 중 유형 변경: 기존 `reset()`에 따라 검색어가 비워지므로 최근
  목록을 다시 표시한다.

## 시각 사양

- 섹션 레이블: 12px, `var(--muted)`, 하단 간격 6px
- 카드 폭: 64px 내외, 카드 간격 8px
- 포스터: 56×84px 또는 동일한 2:3 비율, radius 6px
- 제목: 12px, 중앙 정렬, 한 줄 말줄임
- 카드 배경과 테두리는 기본적으로 투명하게 두고 hover/focus에서
  `var(--surface-2)`와 `var(--accent)`를 사용한다.
- 모션은 120~160ms 색상 변화만 사용하고 `prefers-reduced-motion`을 따른다.

## 검증 항목

단위 테스트:

- 최신순 목록에서 `contentId` 중복을 제거하고 최대 5개를 반환한다.
- 포스터가 없는 항목도 결과에서 제외하지 않는다.
- 빈 목록은 빈 배열을 반환한다.
- `contentId`로 생성하면 새 콘텐츠를 만들지 않고 기존 콘텐츠에 기록을 연결한다.
- 존재하지 않는 `contentId`, 외부 ID와 함께 보낸 `contentId`는 거부한다.

컴포넌트 동작 확인:

- 최근 카드 선택 시 기존 선택 완료 프리뷰와 저장 payload가 올바르다.
- 검색어 입력 시 최근 영역이 숨고, 검색어 삭제 시 다시 보인다.
- `변경` 후 날짜·반응·감상이 유지된다.
- 키보드만으로 카드 선택과 저장이 가능하다.
- 모바일 320px 폭에서 모달이 가로로 넘치지 않고 카드 영역만 스크롤된다.
